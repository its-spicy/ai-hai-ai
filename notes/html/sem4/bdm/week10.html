1. The Combinatorial Space Explosion

Imagine you run a shop with m different products. Every customer walks out with a basket (a transaction), and you want to discover which products tend to be bought together. Before any clever mining can start, you must face an uncomfortable truth: the number of possible combinations is enormous. This is the combinatorial space explosion, and it shows up in two places — the itemset space and the association rule space.

1.1 The Itemset Space

An itemset is any non-empty subset of the available items. Each of the m items is either in or out of a subset, which gives 2m subsets in total. Remove the empty set and we get:

Number of possible itemsets=2m−1

Example with m=3, items {A,B,C}:

23−1=8−1=7

Listing them by size:

Size Itemsets Count
1 {A}, {B}, {C} 3
2 {A, B}, {A, C}, {B, C} 3
3 {A, B, C} 1

The sizes add up correctly: 3+3+1=7.

Each arrow goes from a smaller itemset to a larger one that contains it. Remember this picture — it becomes the map we prune later.

Now scale it up. With only m=20 items:

220−1=1048576−1=1048575

More than a million candidate itemsets from just twenty products. The growth is exponential in m (the number of items), so the problem does not scale gracefully.

Items (m) Possible itemsets (2m−1)

1.2 The Association Rule Space

An association rule has the form X→Y, where X (the antecedent) and Y (the consequent) are non-empty, disjoint itemsets. Every itemset can be split into rules in several ways, so the rule space is even larger than the itemset space.

  • From the itemset {A, B} we get the rule A → B (and also B → A).
  • From the itemset {A, B, C} we get rules such as A → BC and AC → B (and more).

How many rules does a single itemset produce? A k-itemset can be split by choosing which items go to the left side. Any non-empty proper subset can be the antecedent, giving:

2k−2 rules

Check: k=2⇒22−2=2 rules, and k=3⇒23−2=6 rules. This matches the diagram above.

Note for Review — Pro-Tip: The total number of rules over m items follows from a neat argument: every item is either in X, in Y, or in neither, giving 3m assignments. Remove those where X is empty (2m) and those where Y is empty (2m), then add back the doubly-removed case where both are empty (1):

3m−2⋅2m+1

For m=3: 27−16+1=12 rules (six from the three pairs, plus six from the triple). For m=20: roughly 3.48 billion rules. This formula often appears in exam counting questions.

1.3 Direction Matters

Take the three items {A,B,C} with m=3. Even for this tiny set the rules include:

  • A → BC and BC → A
  • B → AC
  • C → AB

(plus AB → C and AC → B, completing the six). Notice that X→Y is not the same rule as Y→X. The reason is that the strength of a rule is a conditional probability, and conditional probability is not symmetric:

P(B∣A)=P(A∣B)

Intuitively, "among people who buy A, how many also buy B?" is a different question from "among people who buy B, how many also buy A?". The two answers share the same numerator (how often A and B appear together) but have different denominators (how often A appears versus how often B appears).

2. Why ARM Needs a Search Strategy

Putting the two explosions together, Association Rule Mining (ARM) has to search a space that grows exponentially in the number of items, and then grow even faster once rules are formed. Checking every itemset against every transaction is simply not realistic.

So ARM requires pruning: a search strategy that throws away large regions of the space without ever looking at them in detail. The rest of this chapter builds exactly such a strategy, and shows how much work it saves.

3. Frequent Itemsets and Minimum Support

Before we can prune, we need a precise way to say "this itemset is interesting enough to keep". That measure is support.

supp(X)=total number of transactionsnumber of transactions containing X​

An itemset X is called frequent if its support reaches a user-chosen threshold, the minimum support smin​:

supp(X)≥smin​

Worked example. Let smin​=0.5 and suppose we have six transactions T1​,T2​,…,T6​. Then X must appear in at least:

0.5×6=3 transactions

So an itemset appearing in only 2 of the 6 transactions is infrequent, while one appearing in 3 or more qualifies.

Note for Review — Pro-Tip: Work with support counts (whole numbers of transactions) whenever you can; they avoid rounding mistakes. Convert the threshold once: smin​×N. In the main example below, 40%×10=4 transactions, and an itemset with exactly 4 occurrences is still frequent because the condition is "greater than or equal to".

4. The Apriori Property

Here is the big idea that makes pruning possible.

Apriori Property: If an itemset is frequent, then every non-empty subset of that itemset is also frequent.

Why does this hold? Any transaction that contains a larger itemset automatically contains each of its subsets. So a subset can never be rarer than the itemset built from it. In symbols, if X⊆Y:

supp(X)≥supp(Y)

The contrapositive — the one we actually use

Flip the statement around and it becomes a pruning weapon:

If an itemset is infrequent, then every superset of it is also infrequent.

Example. Suppose X={A,B} is infrequent. Then every itemset containing both A and B is doomed:

  • {A, B} → infrequent
  • {A, B, C} → infrequent (superset of {A, B})
  • {A, B, C, E} → infrequent (superset of {A, B})

Note for Review — Pro-Tip: The property works in one direction only. "Frequent ⇒ all subsets frequent" is guaranteed. The reverse is not: two frequent items can still form an infrequent pair. In the example below, B (80%) and C (50%) are both frequent, yet {B, C} (30%) is not. Exams love this trap.

5. Apriori Pruning in Action

Time to see the machinery run. We have m=5 items (A, B, C, D, E) and ten transactions.

Transaction Itemset
T1 A, B, C
T2 A, B
T3 A, C
T4 B, D
T5 A, B, C
T6 B, D, E
T7 A, C
T8 A, B
T9 B, C, D
T10 A, B

The full space has:

25−1=31 possible itemsets

We set the minimum support to 40%, meaning an itemset must appear in at least 4 out of 10 transactions.

Step 1: Evaluate the 1-itemsets

Count how many transactions contain each single item, then convert to a percentage by dividing by 10.

Candidate Found in Support Count Support Action
A T1, T2, T3, T5, T7, T8, T10 7 70% Keep
B T1, T2, T4, T5, T6, T8, T9, T10 8 80% Keep
C T1, T3, T5, T7, T9 5 50% Keep
D T4, T6, T9 3 30% Infrequent, discard
E T6 1 10% Infrequent, discard

The surviving set of frequent 1-itemsets is:

L1​={A,B,C}

Here comes the first big saving. D and E are infrequent, so by the Apriori property every superset of D or E is infrequent too. We discard them all without counting a single one:

Infrequent item Example supersets that are discarded Action
D AD, BD, CD, DE, BCD Infrequent, discard
E AE, BCE, ADE, ABCDE Infrequent, discard

These are only examples. Let us count exactly how many itemsets are wiped out:

  • Proper supersets of D: choose any subset of the other 4 items to add, excluding the empty choice: 24−1=15.
  • Proper supersets of E: likewise 24−1=15.
  • Itemsets containing both D and E (counted twice above): the other 3 items are free, so 23=8 (this includes {D, E} itself).

By inclusion–exclusion:

15+15−8=22 itemsets removed without counting

Step 2: Evaluate the 2-itemsets

Candidates are now built only from the survivors {A, B, C}, which gives just three pairs instead of ten. Count the transactions containing both items:

Candidate Found in Occurrence Support Action
AB T1, T2, T5, T8, T10 5 50% Keep
AC T1, T3, T5, T7 4 40% Keep
BC T1, T5, T9 3 30% Infrequent, discard (pruned)

AC sits exactly on the boundary: 4 occurrences equals the required 4, so it survives. BC falls one short and is pruned. The frequent 2-itemsets are:

L2​={AB,AC}

Here is the support of every itemset examined so far, against the 40% threshold:

What the axes represent: each bar is an itemset and its height is its support percentage. The dashed horizontal line marks the 40% minimum support. Bars at or above the line survive; bars below it are pruned.

Step 3: Evaluate the 3-itemsets

We started with the five items {A, B, C, D, E}. After Step 1 only {A, B, C} remain, so the only possible 3-itemset is {A, B, C}.

Does it deserve a count? No. {A, B, C} is a 3-itemset, but it is a superset of {B, C}, and {B, C} was found infrequent in Step 2. By the Apriori property:

{B,C} infrequent⇒{A,B,C} infrequent

Note for Review — Pro-Tip: If you did count it as a sanity check, {A, B, C} appears only in T1 and T5, so its support is 2/10=20%, comfortably below 40%. Apriori simply lets you reach that conclusion without scanning the data.

The pruning picture

Green boxes survived, red boxes were pruned. Notice how the red region swallows a huge part of the lattice the moment D, E, and BC fail.

Step 4: Summary of all levels

Level What remains Action
L1​ A, B, C Frequent
L2​ AB, AC Frequent
L3​ ∅ No frequent 3-itemsets
L4​ ∅ No frequent 4-itemsets
L5​ ∅ No frequent 5-itemsets

Once L3​ is empty the search can stop early: a frequent 4-itemset would need all its 3-item subsets to be frequent, and none exist. The same logic kills L5​.

Note for Review — Pro-Tip: In the board summary for L2​, the entry written next to AB looked like "BC". That cannot be right: BC has only 30% support and was pruned in Step 2. The correct frequent pair is AC (40%), which also matches the Step 2 table and the final answer.

6. What Did Pruning Save Us

Count the support evaluations we actually performed:

Actual support evaluations=5+3=8

Here, 5 are the single items (A, B, C, D, E) and 3 are the pairs (AB, AC, BC). Out of the 31 possible itemsets, the number we never had to evaluate is:

Potential evaluations avoided=31−8=23

These 23 split exactly as: 22 itemsets containing D or E (Step 1) plus 1 more, {A, B, C} (Step 3). The percentage saved is:

3123​≈0.742≈74% reduction

The final frequent itemsets are everything that survived, L1​∪L2​:

{A}, {B}, {C}, {AB}, {AC}

That is five frequent itemsets, and we found them while counting only eight.

Note for Review — Pro-Tip: The final list written on the board was {A, B, AB, AC}, with C left out. But C has 50% support, well above 40%, and it passed Step 1 as a "Keep". It belongs in the answer, and it is also needed: AC being frequent requires C to be frequent (Apriori property).

Note for Review — Pro-Tip: Support is symmetric (supp(AB) is one number), but rules built from {A, B} are not. Using the counts above: P(B∣A)=5/7≈0.714 while P(A∣B)=5/8=0.625. Same itemset, different rule strength — which is exactly why direction matters in Section 1.3.

7. Domain Knowledge as a Second Pruner

Step back and look at the strategy as a whole. We began with {A, B, C, D, E}, which gave 25−1=31 possible itemsets. The Apriori property let the data itself shrink that space: each time a small itemset failed, all of its supersets failed with it. The result is that ARM's search strategy is reduced from the whole lattice to a thin slice of it.

Apriori prunes using evidence found in the data. But prior or domain knowledge pruning can be done as well: if the business already knows that certain combinations are meaningless or impossible, those itemsets (and all their supersets) can be removed from the search before any counting begins. Data-driven and knowledge-driven pruning complement each other.

8. Practice Questions

These are not recall questions. Each one asks you to reason with the ideas above.

  1. The shrinking budget. A shop stocks 10 items. After counting the single items, only 6 turn out to be frequent.

    • (a) What is the largest number of itemsets (of any size) that could still turn out to be frequent?
    • (b) Out of the 210−1 possible itemsets, how many can be eliminated without ever counting them?
    • (c) Why is your answer to (a) only an upper bound? Use a concrete case from the worked example to explain why many of those itemsets still would not survive.

  2. Lowering the bar. Return to the ten-transaction table and lower the minimum support from 40% to 30%. Run Apriori again from scratch. What are L1​, L2​ and L3​? Which candidate 3-itemsets are never counted, and exactly which infrequent subset kills each one? Does {A, B, C} get counted this time, and what does its support finally decide?

  3. One itemset, two stories. Using the table, compute P(B∣A) and P(A∣B) from the itemset {A, B}. A manager claims, "{A, B} is frequent, so A → B and B → A are equally good rules." Critique this claim with your numbers. Then, for the full 5-item problem, how many association rules exist in total (hint: each item sits in the antecedent, the consequent, or neither)? How many can be generated from the frequent itemsets of size at least two that Apriori found? What does the ratio tell you about when pruning must happen relative to rule generation?

  4. Knowledge versus data. Suppose the shop manager says, "D and E are two mutually exclusive versions of the same product; no customer ever buys both." Before reading any transaction, how many of the 31 itemsets can she remove using only this knowledge? Now compare this with what the data-driven Apriori run removed in Step 1. Is her knowledge adding anything the data-driven pruning would not have found anyway? Think about what would change if the minimum support were very low.

  5. Top-down or bottom-up? A colleague proposes searching from the top: "Check the biggest itemset {A, B, C, D, E} first. If it is frequent, every subset is frequent, so we skip counting them all." (a) Which property justifies this reasoning, and why is it logically valid? (b) In this dataset, why would the idea fail to save anything, and why do bottom-up methods tend to win when smin​ is high? (c) Describe a dataset, in words, where the top-down idea would be extremely efficient.
