Outlier Analysis — What Is an Outlier, Really?

Basics of Data Mining — Week 12

This is the last topic of the course. The syllabus lists several families of techniques for it (distribution/deviation based, classification based, clustering based). Before any technique, though, we need to be honest about one thing: the word outlier is used everywhere in data mining, ML and deep learning, yet it is not a well-defined concept. These notes build that message step by step and then show the (few) tools we can safely use.

1. The Slippery Word Outlier

1.1 The textbook definition

Almost every textbook and most of the literature says something like this:

A data point is an outlier if it is "inconsistent" with the other data points, or if it "deviates" significantly from the other data points.

It sounds convincing: if something does not agree with the rest of the data, or sits far from everything else, surely it is an outlier. The catch is the two words placed in inverted commas, inconsistent and deviates (or any similar phrase such as "does not follow the pattern of the data"). They raise two practical problems that never go away.

1.2 Problem 1: quantification

To say "this point deviates a lot" we must measure deviation, and there are many ways to do it. From a handful of numbers you can compute a distance, a correlation, a cross-correlation, the mean, the median, the mode, and so on. Simply having a way to quantify is not enough: which measure should we choose, and why?

This is the same kind of question as "which classifier do I use: a neural network, a decision tree, an SVM, or something else?". There is no universal answer. The only honest way out is to understand the underlying idea of each method and decide whether it matches your situation.

1.3 Problem 2: subjectivity and application-specific input

It is almost impossible to talk about outliers without knowing the underlying application, the domain knowledge and the integrity of the data you are using.

This ties in with a message repeated throughout the course: data mining does not start with an algorithm. You cannot take a data set and say "I will run association rule mining" or "I will run k-means" or "I will train a neural network" straight away. Those steps come only after you have got your data. Outliers are a statement about the data itself, which sits before all further processing, so you need some understanding of what each data point is really about before deciding whether it is an outlier.

1.4 A tiny example that is not as obvious as it looks

Take the data points

1,2,3,52

Most people immediately say "52 is the outlier". The usual reasoning is: the first three numbers differ by only 1 each (1+1=2, 2+1=3), while 52 differs from them by a huge amount, so it is inconsistent, and we can quantify that through differences. That argument is flawed, because we do not know what the number 52 actually means or where it came from. For some process, 52 may be perfectly valid. For another process it may even be 3 that is impossible.

Of course you can still compute many numbers from these four values (mean, median, mode, a correlation if you have pairs). That is not the problem. The problem is that computing a number does not justify calling a point an outlier.

Note for Review Pro-Tip: Exams like to ask "Is the point X an outlier?" with a tiny data set. Remember that the numerically large point is only a candidate. A defensible answer states the reference model or threshold you used, or the process knowledge that makes the value impossible or rare.

2. Data Has a Backstory

Early in the course, data was related to functions and to the process that generates it. Images, audio and so on are all produced by a physical process. To judge whether a value such as 52 is an outlier, you have to understand that physical process. Equivalently:

A point is an outlier only if the process that generated it should not have produced that value.

This is also the answer to a classic question about why we analyse outliers: an outlier signals an anomaly in the data, and the important part is that the anomaly originates from the process itself. A random number being far from other numbers is not enough.

3. Outliers Through Distributions

To keep things objective and grounded, one common way to define outliers is through a distribution.

3.1 Extreme values

Imagine the histogram of your data (in practice the data points are lined up into a histogram). The distribution need not be normal. Most points pile up in the middle, and very few points lie far to the left or far to the right.

  • Pick a line somewhere in a tail (it could be here, or here, or here: the position is your choice).
  • Everything beyond that line is called an extreme value.
  • Extreme values are then equated with outliers.

They are called extreme because they occur rarely compared with the values in the bulk of the distribution. This is part of basic statistics (hypothesis testing, elementary probability).

The key idea: the distribution is a model of the process that generated the data. We treat it as the reference model, and whatever lies in its tails is declared extreme.

3.2 Definition versus usefulness

  • As a definition, this is perfectly fine for a procedure: "anything in the tail is an outlier".
  • It does not say whether the point is useful. In practice extreme values are often very useful: they tell you that something is wrong, or that something different is happening, and that is exactly why they sit in the tail.
  • So defining an outlier and using it are two different questions. Right now we only discuss the first one.

3.3 The reference distribution can change

Suppose the data is temperature and the observed value is 40∘C.

  • In a place that is cold in general, most temperatures are near 0 (or lower) and 40∘C is rarely seen. It lies far in the tail, so it is an extreme value.
  • In a place that is quite hot, 40∘C is common. It lies somewhere in the middle of the distribution, so it is not an outlier. You would look at other values to find extremes.

The red dashed line is the same 40∘C reading. Under the blue model it is deep in the right tail, under the orange model it is quite ordinary. (The two Gaussians drawn here are illustrative, not data from the lecture.)

So you must state your reference model clearly: "40∘C is an outlier with respect to this distribution". Change the distribution (or take the same value at another place) and it may no longer be an outlier. This is the relative nature of outliers.

Note for Review Pro-Tip: "Outlier" is always short for "outlier with respect to a reference model". If an exam question does not give the model, say which one you assume.

4. The Gaussian Shortcut and Z-Scores

4.1 Standardization

The most common reference distribution is the Gaussian (normal) distribution with

  • mean μ
  • standard deviation σ

Here x can be anything: a temperature, a weight, and so on. We standardize it by shifting the mean to zero and scaling by the standard deviation:

z=σx−μ​

Subtracting μ shifts the curve so that it is centred at 0, and dividing by σ rescales the spread to 1. The variable z tells you how many standard deviations x is away from the mean.

4.2 The "3 sigma" convention

By convention, if

∣z∣>3

we flag x as an outlier.

Example: you have temperature data and you are asked whether x=52∘C is an outlier. μ and σ are known, so you compute

z(52)=σ52−μ​

If z(52)>3, then 52∘C is declared an outlier.

Illustration with assumed numbers (μ=30, σ=6, not from the lecture):

z(52)=652−30​=622​≈3.67>3⇒flagged

The shaded red areas are the tails beyond ∣z∣>3. For a true Gaussian they contain only about 0.27% of all points, which is why the rule feels "safe".

This is a matter of procedure. We are not claiming it is useful for your problem, only that it is a clear rule for flagging a point.

4.3 Arbitrary distributions: a threshold c

If the distribution is not Gaussian you can fall back to the original idea and define a threshold c:

  • x<c⇒ not an outlier
  • x>c⇒ outlier

For the temperature example, if c=45∘C, then any temperature above 45∘C is qualified as an outlier. This works for any distribution, as long as the distribution actually has a tail. If there is no tail, the idea makes little sense.

Note for Review Pro-Tip: The "3" in ∣z∣>3 and the "c" in the threshold rule are choices, not laws of nature. Both amount to deciding where to draw the line in the tail.

One wrong value can ruin a model. Take a very simple regression experiment.

5.2 One typing error

Suppose, because of a data-entry mistake or a faulty measurement, the last value 12 is recorded as 40. Only one of six numbers is wrong. Refit:

Prediction at x=4 8.01 14.68 almost doubled

A single bad point made the slope three times larger, and every prediction made with that line is now badly off. That is why outlier analysis is useful: if the machine producing the data is recalibrated or the data is collected again, the damage disappears.

5.3 The catch

Suppose you were only handed the final data with 40 in it. How would you know that 40 is an outlier? That question comes before "what is an outlier", and it is the real difficulty. You can only answer it if the application tells you that a value like 40 is impossible or very rare here. Only then do you say: "this point looks out of place, let me re-calibrate the machine, take the data again, or apply corrective measures". The phrase "out of place" has to be characterized by the application itself.

Note for Review Pro-Tip: This is a standard demonstration of how least squares is not robust: squared errors give a far-away point a huge pull on the fitted line. Remember the numbers 1.99→5.99 and 8→14.68.

6.2 The threshold decides the answer

Rule Is 50 flagged? (z=1.71) Is 52 flagged? (z=1.82)
∣z∣>3 No No
∣z∣>1.8 No Yes
∣z∣>1.7 Yes Yes
∣z∣>1.5 Yes Yes

With the conventional ∣z∣>3, neither point is an outlier. With ∣z∣>1.5, both are. The outlier status now depends on an arbitrary number. So the threshold must have some logic or meaning behind it; "I will take 3, or 1.5, or 2.5" is not a justification. Without domain knowledge about the process (for example, knowing that the process cannot generate such values) you cannot defend either choice. With that knowledge you could say these are outliers without any computation at all.

Note for Review Pro-Tip: There is a built-in reason why ∣z∣>3 could never fire here. With the sample standard deviation, the largest possible ∣z∣ in a sample of size n is n​n−1​. For n=9 this is 38​≈2.67<3. The outliers also inflate xˉ and s themselves (xˉ=19.44 is far from the typical 10 to 11), which hides them (a masking effect).

7. What to Do After Detection

Assume the outliers have been detected correctly. There are three standard actions:

  • Remove them: the data set now has only 7 points instead of 9.
  • Replace them, for example by some sort of averaging.
  • Collect the data again, hoping that with more care these values will not reappear.

This part is straightforward. The challenging part is how to define and detect the outliers.

8. Box Plots and the IQR Rule

Box plots were covered in earlier lectures (quartiles and the interquartile range). They give a visual way of analysing outliers, with the assumption that the number of outliers is not too high.

8.1 Example

Data (already sorted, n=12):

3,5,6,6,7,8,8,9,10,11,12,30

Split the sorted data into a lower half and an upper half of 6 values each, and take the median of each half:

  • lower half 3,5,6,6,7,8 gives Q1​=26+6​=6
  • median of all data: 28+8​=8
  • upper half 8,9,10,11,12,30 gives Q3​=210+11​=10.5
IQR=Q3​−Q1​=10.5−6=4.5

The five values to plot are the minimum, Q1​, median, Q3​ and maximum. A threshold is then used to decide which points are outliers. The usual convention (Tukey's fences) is 1.5×IQR beyond the quartiles:

1.5×4.5=6.75Lower fence=Q1​−6.75=−0.75Upper fence=Q3​+6.75=17.25

Everything between −0.75 and 17.25 is inside the fences. The value 30>17.25, so 30 is flagged. The upper whisker stops at the largest non-outlier, which is 12.

The box covers Q1​ to Q3​, the dark tick is the median, the grey line is the whisker, the red dashed line is the upper fence, and the red dot is the flagged point.

Note for Review Pro-Tip: Different textbooks and software compute quartiles slightly differently (median of halves, interpolation), so Q1​ and Q3​ can shift a little. Always state the method. Also note that the fence multiplier 1.5 is again a convention, in the same spirit as ∣z∣>3.

9. Procedures vs Process

If you search the literature you will find a great many outlier detection methods. They are mostly procedures: do step 1, step 2, step 3; if the quantity exceeds something, declare an outlier. You can follow them, but the bigger concern is whether the data came from a certain process and whether you know anything about that process.

The syllabus also lists classification-based and clustering-based outlier detection. These will be handled in the final lecture. The same issue remains (what is an outlier?), and since classification and clustering are added, there is one extra layer on top of it.

10. Domain Knowledge

The best way to deal with outliers is domain knowledge. Know the application, what the data is, and how the underlying process behaves.

10.1 Medical example: blood pressure and lab reports

Where does the reference value for blood pressure come from? From a lot of data collected at hospitals and laboratories: data from 1000 or even 1 million patients is turned into a histogram or distribution, and a threshold is defined from it. When a doctor says "your blood pressure is high", they are comparing against that limit, which is in effect an average over everyone who has taken the test.

Lab reports work the same way. Suppose the reference range is 1 to 4:

  • A value of 4.5 is formally outside the range, but a doctor will probably not be worried: it might go away on its own. The range came from past data and has natural variation.
  • A value of 10.9 deviates a lot from the range and is a cause for concern.

Also, there is no sharp mathematical edge. You do not say "5.1 is fine but 5.11 is an outlier". You have a sense that up to about 5.1 is fine, and 5.2 may not be a problem either. That approach is slightly subjective, and that is exactly the point.

10.2 Physical measurements

  • A microphone you are using: you get used to the sound pressure levels it records. A very large value makes you ask whether it is even physically possible.
  • A camera (images): the same reasoning applies to the pixel values it can produce.

12. Practice Questions

Q1 — The sensor that hid its own faults. A factory logs the nine temperature readings 10,11,9,10,12,11,10,50,52 and uses the rule ∣z∣>3 with the sample mean and sample standard deviation. Show, without computing a single z-value, why this rule can never flag any point of a nine-point data set. Then suppose the factory keeps logging and collects 100 more ordinary readings (around 10 to 11) while 50 and 52 stay in the set. Estimate roughly what happens to z(52), and explain what this tells you about using the rule on very small samples.

Q2 — Two rules, two verdicts. For the same nine readings, apply the box-plot (Tukey fence) rule with quartiles taken as medians of the lower and upper halves (leave out the overall median when n is odd). Does it flag 50 and 52? Compare with the z-score rule. Why might a method based on quartiles behave differently from a method based on the mean and standard deviation when there are two extreme values, not one? What does this suggest about trusting any single detector?

Q3 — Where the typo lands matters. In the regression experiment the corrupted point was at x=6, the end of the data, where y jumped from 12 to 40. Suppose instead the same typo (+28 added to the true value) happened at x=3, the middle of the data. Without fully refitting, reason about the use of ∑(xi​−xˉ)yi​ to predict whether the slope will change more, less, or the same compared with the x=6 case, and whether the intercept will change. Then confirm by computing the new slope.

Q4 — One thermometer network, two climates. A weather agency pools temperature readings from a very cold mountain town and a hot desert town into one data set and applies the rule ∣z∣>3 using the pooled mean and standard deviation. Describe which readings are likely to be flagged and which genuine anomalies are likely to be missed. Propose a better design for the reference model and justify it using the idea that the distribution is a model of the process generating the data.

Q5 — The alarm that cried wolf. A hospital software engineer wants to automate lab-report alerts: "if the value is above 4 (the upper edge of the reference range 1 to 4), raise a critical alarm". Values 4.5 and 10.9 arrive. Discuss what happens with the hard cutoff, why doctors treat the two values differently, and design a graded alert scheme that uses the historical distribution of the test results (for instance, the idea of a threshold c and a distance in standard deviations) while still leaving room for clinical judgement. What information would you need before trusting your thresholds?
