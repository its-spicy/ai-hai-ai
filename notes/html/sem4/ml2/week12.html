1. Where Autoencoders Live: Supervised vs Unsupervised Learning

This is the last lecture of the course. The previous lecture finished the basics of CNNs. Today's topic is autoencoders, and we also briefly touch generative AI, which later courses cover in depth.

1.1 Supervised Learning (recap)

Input: Labeled data (x,y). For every data point x we know the corresponding label y.

Goal: Learn a mapping to predict labels as accurately as possible for unseen points.

Suppose training data are x1​,…,xn​ with ground-truth labels y1​,…,yn​. For a new point xnew​ that is not in the training set, we want a predicted label y^​new​ as close as possible to its (unknown) ground-truth label.

Examples: Classification, object detection (what kind of object is in the input), semantic segmentation (the label of each pixel of an image), image captioning (the best caption for an image), 3D reconstruction, etc.

These problems are solved well by supervised techniques because for each of them we have ground-truth labels:

  • Classification: each image has a label. Cat images are labelled cat, sunflower images sunflower, puma images puma.
  • 3D scene understanding: all the objects in a 3D scene (chairs, a table, ...) are detected and segmented, each with its own label.
  • 3D shape / human-body reconstruction: the predicted shape is compared against a known ground-truth shape.

(The lecture illustrations are credited to Engelmann et al. 2020 and Atzmon et al. 2020.)

1.2 Unsupervised Learning

Input: Just data, no labels.

Goal: Learn the underlying structure of the data.

Examples: Clustering, dimensionality reduction, density estimation, depth from a single image, etc.

Since labels are not given, all we can do with raw data points is discover their structure. For example, we can ask from which distribution the points were sampled.

Problem What we are given What we want
Clustering A set of data points Group them into clusters by looking only at feature patterns
Dimensionality reduction Points with a huge number of features (some redundant or linearly dependent) Fewer features per point, keeping only the salient ones and throwing away redundant and linearly dependent ones
Density estimation Samples from some distribution The entire distribution they came from
Depth from a single image A single RGB image A depth map, with no ground-truth depth used for supervision

(Illustrations: concentric-ring clusters, a pair of Gaussians with samples, 3D face reconstruction from Wu et al. 2020, and single-image depth from Zhou et al. 2017.)

1.3 Side-by-side comparison

Aspect Supervised Unsupervised
Data (xi​,yi​) pairs xi​ only
Goal Predict labels of unseen points Learn the structure of the data
Typical tasks Classification, detection, segmentation, captioning, 3D reconstruction Clustering, dimensionality reduction, density estimation
Loss compares... Prediction vs ground-truth label Needs a trick, because no ground truth exists

How you solve each problem is up to you. You can apply classical methods such as an SVM directly on the features of a data point, or use a neural network. We already know how to use neural networks for supervised problems. Autoencoders are a neural-network technique for the unsupervised problems above.

2. Distribution Estimation and Generative Models

2.1 The distribution estimation problem

We are given only samples drawn from some distribution. We must find the parameters of the underlying distribution that generated them.

  • 1-D: Samples lie on a line (one feature each), drawn from a Gaussian. We must find its mean and variance.
  • 2-D: Each point has two features. We must find the mean vector and covariance matrix of the underlying distribution.
  • N-D: The general case. Example: given a set of butterfly images, learn the distribution of all butterfly images that can exist in the world.

The 1-D case is illustrated below. The curve is a standard Gaussian density, and the red dots on the axis are a few (illustrative) samples we would observe.

2.2 Generative models

Once we have learned the underlying distribution, we can sample new data points from it, for example new butterfly images that may not exist in the real world.

Distribution estimation is the basic building block of all generative AI algorithms. Models that learn a distribution so that they can sample from it are called generative models.

Definition. Given a training dataset, learn the underlying distribution such that we can generate new samples from the same distribution.

  • The training points are samples from an unknown distribution pdata​(x). Only the samples are available to us, never pdata​ itself.
  • We must find a distribution pmodel​(x) that is as close as possible to pdata​(x).
  • We then generate new samples from pmodel​(x). Because pmodel​≈pdata​, the new samples look as if they had been drawn from pdata​.

Central question: How can we learn pmodel​(x) as close as possible to pdata​(x)?

2.3 Taxonomy of generative models

Many algorithms exist for this problem. They are not the focus of this course and will be covered in generative AI courses. The family tree below shows how they are organised. The highlighted ones are the ones named in the lecture.

  • GAN is a very famous technique.
  • Boltzmann machines are another famous technique.
  • Diffusion models then entered the picture and overtook the other generative models because they perform exceedingly well on challenging datasets.
  • Autoencoders are the building block of many generative models. The Variational Autoencoder is a direct descendant of the ideas in this lecture.

3. Dimensionality Reduction and PCA Revisited

Before autoencoders, recall dimensionality reduction from ML-1 (Principal Component Analysis).

3.1 Problem setup

Let X={xi​:xi​∈Rd}i=1n​ be the input dataset. Each point has d features, and we have n points. This is an unsupervised problem: no labels are given.

We want a lower-dimensional representation y∈Rk with k≪d.

3.2 Modelling the mapping linearly

There are many ways to build this mapping. PCA models it as a matrix multiplication:

y=Wx

Since the input has dimension d and the output has dimension k, the matrix must be

W∈Rk×d,k<d

So Wx∈Rk is the lower-dimensional representation of x. W is called the encoding matrix.

3.3 Why we cannot write a normal loss

In supervised learning we would compare the prediction y^​ with a ground-truth label. Here nobody tells us which features out of the d are the important ones. The ground-truth salient features are not available, so we cannot compare y^​ with anything. How do we find W then?

3.4 The key idea: reconstruct

While reducing from d to k features we should retain as much information as possible. A good test of this is to ask whether we can recover the original point from the k features.

Coin analogy. You hold six coins: ₹1, ₹2, ₹5, ₹10, ₹20, ₹200, and you may keep only k=3 of them. To lose the least value you throw away the three coins that contribute least to the total.

total=1+2+5+10+20+200=238thrown away=1+2+5=8,retained=238−8=230fraction retained=238230​≈0.966=96.6%

The three kept coins represent almost the whole sum. PCA does the same thing with features: keep the k directions that carry most of the information.

The recovery is also a linear transformation. We need a matrix going from k dimensions back to d dimensions, so

U∈Rd×k

For the dimensions to match, Uy must be a vector in Rd, which is exactly what U∈Rd×k gives. U is the decoding matrix.

The full pipeline is:

x∈RdW∈Rk×d​Wx∈RkU∈Rd×k​UWx∈Rd

Call the reconstruction xˉ (or x^):

xˉ=Uy=UWx

3.5 The PCA loss

We want the original and the reconstruction to be as close as possible, and this must hold for every data point. This is the same squared-error loss we used in linear regression:

W∈Rk×d,U∈Rd×kargmin​i=1∑n​∥xi​−UWxi​∥22​

3.6 The PCA solution

The solution was derived in ML-1, so we only recall it. Assume the data are mean-centred. Build the covariance matrix

C=n1​i=1∑n​xi​xi⊤​

Then

U=[u1​u2​⋯uk​],W=U⊤

where u1​,…,uk​ are the eigenvectors of C corresponding to the k largest eigenvalues.

Why the largest eigenvalues? There are formal proofs, but the intuition is this. The eigenvectors are the principal directions, and each eigenvalue is the variance of the data along its direction. Keeping the k directions of maximum variance keeps the most information.

3.7 Full numeric walk-through (tiny example)

Take d=2, k=1 and four mean-centred points:

a=[21​],b=[−2−1​],c=[12​],e=[−1−2​]

Step 1: outer products.

aa⊤=[42​21​],bb⊤=[42​21​],cc⊤=[12​24​],ee⊤=[12​24​]

Step 2: covariance matrix.

C=41​[108​810​]=[2.52​22.5​]

Step 3: eigenvalues.

det(C−λI)=(2.5−λ)2−22=0⇒2.5−λ=±2⇒λ1​=4.5,λ2​=0.5

Step 4: eigenvector of the largest eigenvalue λ1​=4.5:

(C−4.5I)u=[−22​2−2​]u=0⇒u1​=2​1​[11​]

Step 5: build the matrices (k=1):

W=u1⊤​=2​1​[1​1​]∈R1×2,U=u1​=2​1​[11​]∈R2×1

Step 6: encode point a.

Wa=2​1​(1⋅2+1⋅1)=2​3​≈2.121

Step 7: decode.

UWa=2​1​[11​]⋅2​3​=[1.51.5​]

The same result comes from the combined matrix UW:

UW=21​[11​11​],UWa=21​[11​11​][21​]=21​[33​]=[1.51.5​]

Step 8: reconstruction error of a.

a−UWa=[0.5−0.5​],∥a−UWa∥22​=0.25+0.25=0.5

By symmetry, c reconstructs to (1.5,1.5) and b,e reconstruct to (−1.5,−1.5). Each point has squared error 0.5:

i=1∑4​∥xi​−UWxi​∥22​=4×0.5=2.0

Note for Review: The average error per point is 2.0/4=0.5=λ2​, which is exactly the discarded eigenvalue. In general, PCA's average reconstruction error equals the sum of the eigenvalues you threw away. This is the formal version of the coin analogy.

4. The Autoencoder

4.1 Definition

An autoencoder is a neural network that is trained to attempt to copy its input to its output.

The idea is exactly the one behind PCA. The only difference is that the linear maps W and U are replaced by neural networks:

PCA Autoencoder
Encoding matrix W∈Rk×d Encoder (a neural network)
Compressed code Wx∈Rk Hidden unit / code h
Decoding matrix U∈Rd×k Decoder (a neural network)
Reconstruction UWx∈Rd Reconstruction x^

Neural networks can represent non-linear mappings (for example with ReLU or any non-linear activation), so autoencoders can model more complex relations between features than PCA can.

4.2 Internal structure

Internally the autoencoder has a hidden layer h that describes a code used to represent the input. The network consists of two parts:

  • An encoder function h=f(x), with f:x↦h
  • A decoder that produces a reconstruction x^=g(h), with g:h↦x^

In the literature the encoding / feature vector is denoted h, and this layer is also called the hidden layer. The end-to-end map is x^=g(f(x)).

4.3 "But we already have the input. Why predict it again?"

If we already hold x, copying it to the output looks pointless. The real product is the code h.

Applying an SVM directly on raw images is hard because an image has a huge number of features (its pixels). So we first train an autoencoder to find the important features. A typical code size is 1024 or 512 numbers, enough to represent a reasonable-resolution image. These learned salient features can then feed any later task, for example an SVM or logistic regression, to solve a classification problem.

4.4 Why perfect copying is useless

If an autoencoder simply learns g(f(x))=x everywhere, it is not especially useful, because it has learned nothing meaningful.

  • Autoencoders are designed to be unable to copy perfectly.
  • They are restricted so that they copy only approximately, and only inputs that resemble the training data.
  • Because the model is forced to prioritise which aspects of the input to copy, it often learns useful properties of the data.

This is the same logic as PCA, where we copy approximately so that redundant features can be thrown away.

5. Undercomplete Autoencoders

One way to force useful features is to make the code smaller than the input:

dim(h)<dim(x)

An autoencoder whose code dimension is smaller than the input dimension is called undercomplete. Learning an undercomplete representation forces the autoencoder to capture the most salient features of the training data.

If h had more features than x we would gain nothing, so the constraint is that it must not exceed the input dimension. (Section 8 shows that even this constraint is not enough when the encoder and decoder have huge capacity.)

5.1 Linear autoencoder = PCA

When both the encoder and the decoder are composed of linear neural nets, the undercomplete autoencoder has

f(xi​)=Wxi​,g(hi​)=Uhi​

and its training objective is

W,Umin​i=1∑n​∥xi​−UWxi​∥22​=Cost function of PCA

It therefore spans the same subspace as PCA.

Why do many linear layers still give a single matrix? Stacking linear layers just multiplies matrices. For two encoder layers W2​W1​ and two decoder layers U1​U2​:

x^=U1​U2​W2​W1​x=(U1​U2​)(W2​W1​)x=UWx

A product of matrices is one matrix, so depth adds nothing without non-linearity. (The subspace matches PCA's; the individual basis vectors need not.)

5.2 Non-linear autoencoder = non-linear PCA

With non-linear encoder f and decoder g (for example ReLU units), the autoencoder can learn a more powerful non-linear generalisation of PCA. PCA can only describe flat (linear) subspaces. A non-linear autoencoder can describe curved subspaces.

Linear data: PCA works. The points lie near a straight line, and the PCA direction (red line) captures them.

Curved data: only a non-linear autoencoder fits. The (illustrative) points follow a parabola y≈x2. The best straight line (red, PCA) misses the structure. The curve (green) is what a non-linear autoencoder can learn.

Note for Review: The best PCA line for this symmetric parabola is roughly horizontal at the mean height (x2=4/3≈1.33 for x∈[−2,2]). Every point is projected onto that line and the vertical information is lost. A non-linear autoencoder can describe the whole curve with one number (position along the curve).

6. Training an Autoencoder

Autoencoders are unsupervised. We only need a set of data points {x1​,x2​,…,xn​}.

Design f and g as neural networks:

  • θe​ = learnable weights of the encoder
  • θd​ = learnable weights of the decoder
  • For each data point, hi​=fθe​​(xi​) and x^i​=gθd​​(hi​)

We want θe​ and θd​ such that the error between the input xi​ and the output x^i​ (which depends on θe​,θd​) is as small as possible. This is the same logic as PCA. The same θe​,θd​ are used for all data points. They do not change as the data point changes.

For each point, pass xi​ through the encoder and then the decoder to get the reconstruction. Then measure the distance between xi​ and x^i​ with any distance metric d(⋅,⋅), for example the 2-norm. The learning process is simply minimising

ℓ(θe​,θd​)=i=1∑n​d(xi​,g(f(xi​)))

With the squared 2-norm as the distance, all of the following are the same quantity:

ℓ(θe​,θd​)=i=1∑n​∥xi​−g(f(xi​))∥22​=i=1∑n​∥xi​−g(hi​)∥22​=i=1∑n​∥xi​−x^i​(θe​,θd​)∥22​

There are other ways to measure the distance between xi​ and x^i​, but the squared 2-norm is the standard one. In practice this loss is minimised with gradient descent and backpropagation through both networks.

Note for Review: The "label" in this supervised-looking loss is the input itself. That is why autoencoders count as unsupervised (more precisely, self-supervised). No human annotation is needed.

7. Worked Example: Fashion-MNIST

A very simple autoencoder you can implement yourself uses the Fashion-MNIST dataset. It contains grayscale images of fashion items such as shoes, t-shirts, shirts and pants.

Architecture (Dense + ReLU):

  • Because the images are small, flatten each one into a single vector. The slide labels this input layer as 728 pixels.
  • One layer is the encoder, mapping the flattened pixels to a hidden layer of only 64 neurons (the code).
  • One layer is the decoder, mapping the 64 features back to 728 outputs, which are reshaped into the reconstructed image.

Note for Review: Fashion-MNIST images are 28×28, which gives 28×28=784 pixels, so the lecture's "728" is almost certainly a slip. The idea is unchanged, but use 784 in code and in calculations.

Small calculations (using 784 inputs):

compression ratio=64784​=12.25×encoder parameters=784×64+64=50,176+64=50,240decoder parameters=64×784+784=50,176+784=50,960total=50,240+50,960=101,200

7.1 What the reconstructions show

Reconstructions on test images (the network was trained on the training set) show that xi​=x^i​. Some information is lost. This is exactly what we want.

  • With only 64 features the autoencoder captures the global structure of an object, for example the overall shape of a shoe.
  • It loses fine-grained detail. A t-shirt's printed texture disappears, and a shirt's checks are washed out.
  • Slowly varying details (low frequency) are kept. Rapid variations (high frequency) are thrown away.
  • To recover the fine detail as well, increase the number of features in the hidden layer.

Low-pass filter analogy. This autoencoder behaves like a low-pass filter: it lets the low frequencies of the input through and blocks the high frequencies. A small code means a blurry-but-recognisable reconstruction. A larger code means a sharper one.

8. Regularized Autoencoders

8.1 The problem: too much capacity

Suppose the encoder and decoder have huge capacity. Even if the code is a single number (dim(h)=1≪d), the network can cheat by memorising the dataset:

f(xi​)=i,g(i)=xi​
Input Encoder output (code) Decoder output
x1​ 1 x1​
x2​ 2 x2​
⋮ ⋮ ⋮
xi​ i xi​
⋮ ⋮ ⋮
xn​ n xn​

The "feature" learned is just the index of the data point, which is not a salient feature. If you shuffled the ordering of the data points, this code would be useless. The copy is perfect, yet nothing useful is learned.

Note for Review: This exact scenario does not happen in practice. It is a thought experiment showing that an autoencoder trained to copy can fail to learn anything useful if its capacity is allowed to become too great. It is the same overfitting story you know from supervised learning.

8.2 The remedy

Ideally we could train any architecture successfully and choose the code dimension and the capacity of the encoder and decoder to match the complexity of the distribution to be modelled. A related headache is the code size itself. Why 64 for Fashion-MNIST and not 512 or 138? It is a tedious hyper-parameter to choose.

Regularized autoencoders avoid limiting capacity by keeping the encoder and decoder shallow and the code small. Instead they use a loss function that encourages other properties besides the ability to copy the input to the output. Those properties include:

  • Sparsity of the representation
  • Smallness of the derivative of the representation
  • Robustness to noise or to missing inputs

A regularized autoencoder can be non-linear and overcomplete and still learn something useful about the data distribution, even when its capacity is great enough to learn a trivial identity function. Its encodings are naturally useful because the model was trained to approximately maximise the probability of the training data rather than merely to copy input to output.

8.3 Sparse autoencoder

A sparse autoencoder is an autoencoder whose training criterion includes a sparsity penalty Ω(h) on the code layer h, for example Ω(h)=∥h∥0​.

The code may be large (any dimension we like), but we want only a few entries to be non-zero. A small number of active features then represent the image, and most entries are exactly zero. The loss is

∥xi​−x^i​(θe​,θd​)∥22​+Ω(hi​)

The first term is the usual reconstruction loss. The second term is the sparsity penalty.

Aside: the p-norm family. For a vector x=(x1​,…,xn​),

∥x∥p​=(∣x1​∣p+∣x2​∣p+⋯+∣xn​∣p)1/p
  • p=2: ∥x∥2​=x12​+⋯+xn2​​, the usual length.
  • p=1: ∥x∥1​=∣x1​∣+∣x2​∣+⋯+∣xn​∣.
  • p→0: the formula would need 1/p=1/0, which is undefined, so the "0-norm" is defined as the number of non-zero entries.

Example. For v=(1,2,0,0,0):

∥v∥0​=2,∥v∥1​=1+2+0+0+0=3,∥v∥2​=1+4​=5​≈2.236

Minimising ∥h∥0​ pushes most entries of h to be exactly 0. Even with a large hidden dimension, only a small set of non-zero entries carries the salient features. In the lecture figure the code looks like hi​=[0,0,1,…,0,1]⊤.

8.4 Contractive autoencoder

If the features are good, a small change in the input should not cause a large change in the hidden representation. The embedding h should not change much for a small change in x.

The rate of change of the code with respect to the input is the gradient of hi​ with respect to xi​. Let hik​ be the k-th entry of the code (the code has several entries, indexed by k). The penalty is

k∑​∥∇xi​​hik​∥22​

and the total loss is

∥xi​−x^i​(θe​,θd​)∥22​+k∑​∥∇xi​​hik​∥22​

Tiny worked step. For a single sigmoid code unit h=σ(w⊤x+b), the chain rule gives

∇x​h=σ′(w⊤x+b)w⟹∥∇x​h∥22​=(σ′(w⊤x+b))2∥w∥22​

So the penalty is small when the weights are small or the unit is saturated (flat). That makes the code insensitive to small input wiggles.

8.5 Denoising autoencoder

A denoising autoencoder (DAE) never shows the clean data point to the encoder. Before feeding xi​ to the encoder, we degrade it, for example by adding noise, to get a corrupted copy x~i​. The encoder sees x~i​, but the decoder is asked to reproduce the clean xi​. The loss is

∥∥​xi​−g(f(x~i​))∥∥​2​

Denoising autoencoders must therefore undo the corruption rather than simply copy the input. A typical corruption is additive Gaussian noise, x~i​=xi​+ϵ with ϵ∼N(0,σ2I).

8.6 Summary of the regularized losses

ℓs​(θe​,θd​)=i=1∑n​∥xi​−x^i​(θe​,θd​)∥22​+λ∥h∥0​ℓc​(θe​,θd​)=i=1∑n​∥xi​−x^i​(θe​,θd​)∥22​+λk∑​∥∇xi​​hik​∥22​

Here ℓs​ is the sparse and ℓc​ the contractive autoencoder loss, and λ controls the strength of the penalty.

Is this regularization similar to the one we used in regression? Recall ridge regression:

ℓr​(θ)=i=1∑n​∥yi​−fθ​(xi​)∥22​+λθ⊤θ

No, it is different. In regression we regularize the weights θ of the model. In sparse and contractive autoencoders we regularize the features (the code h and its sensitivity), not the network weights.

Variant Extra ingredient Behaviour it encourages
Undercomplete dim(h)<dim(x) Capture only salient features
Sparse Penalty λ∥h∥0​ Few non-zero code entries
Contractive Penalty on ∥∇x​h∥2 Code robust to small input changes
Denoising Corrupted input, clean target Learn to undo corruption

There are many more variants in the literature, and you can follow those up on your own.

9. Stochastic Interpretation

An autoencoder can be read in two ways:

Deterministic interpretation. The encoder and decoder are plain functions:

f:x↦h,g:h↦x^

Stochastic interpretation. The encoder and decoder are conditional probability distributions:

p(h∣x)(encoder),p(x∣h)(decoder)
  • Given x, the encoder gives a sample h from p(h∣x). In practice it returns the most likely feature representation for that data point.
  • Given h, the decoder samples a data point from p(x∣h). In practice it returns the most likely data point represented by those features.

Link to modern generative AI. Generative models are built around precisely the decoder distribution p(x∣h). Here h plays the role of a prompt, for example a text description. A text prompt is first converted into a numerical representation, which is then fed to a neural network representing p(x∣h) to produce the most likely data point matching the prompt. This is the genesis of generative models.

10. From Autoencoders to Generative Models

10.1 Restating the goal

Given points {x1​,x2​,…,xn​} from an unknown pdata​(x), learn pmodel​(x) from the samples such that it is as close as possible to the ground truth. Once learned, we can sample new points that behave as if drawn from pdata​. The question is: how do we sample new points from pmodel​(x) in a controlled way?

10.2 Motivating example: faces with attributes

Imagine a dataset of face photos. Each face can be described by semantically meaningful attributes:

Attribute Possible values
Spectacles Yes / No
Expression Sad / Angry / Smiling / ...
Beard Yes / No
Age 1, 2, 3, ...
Viewpoint {0,1,2,3,…,180}
Nose Style Long / Medium / Short
Hair Style Long / Short
... ...

If we could obtain such features from the data, then at test time we could play with those numbers and decide what kind of face we want, for example a smiling person wearing spectacles. Independent, blind sampling from pmodel​ gives no control over what we get, so we must condition the sampling on chosen features.

10.3 Bringing latent variables into the maths

Call the control features latent parameters z=[z1​z2​⋯zk​]⊤. They are latent because they are never directly observed in the data. We bring them in through ordinary probability theory.

Step 1: start with the density we want.

p(x)=p(x)

Step 2: marginalisation. From a joint distribution of two variables we get the marginal of one by integrating out the other:

p(x)=∫z​p(x,z)dz

Step 3: factor the joint (the slide labels this "Bayes theorem"):

p(x,z)=p(x∣z)p(z)

Step 4: combine.

p(x)=∫z​p(x∣z)p(z)dz

Note for Review: Strictly, Step 3 is the product rule (chain rule) of probability. Bayes' theorem is the rearrangement p(z∣x)=p(x)p(x∣z)p(z)​, which is what the encoder side of a VAE approximates. Many courses loosely call both "Bayes". Do not lose marks by mixing them up.

Meaning. Instead of modelling p(x) directly, we model the conditional p(x∣z) and a simple distribution p(z) over features. Conditional distributions let us control sampling. We choose z (for example "smiling, spectacles, young"), then sample x∼p(x∣z) to get a data point that best represents those requirements.

10.4 The generative process as a two-step story

The latent variables z encode semantically meaningful information about x. So it is natural to view generation as two steps:

  1. First generate the high-level semantic information: z∼pz​.
  2. Then generate the actual data from it: x∼p(x∣z).

For the faces example, take six latent features z1​,…,z6​ = (Hair Style, Expression, Beard, Spectacles, Viewpoint, Age). The face is generated as p(x∣z1​,z2​,z3​,z4​,z5​,z6​).

10.5 Can we use autoencoders directly?

The stochastic autoencoder has exactly the right shape:

  • Encoder: p(z∣x), from data to latent features
  • Decoder: p(x∣z), from latent features to data

Two things are still missing:

  1. Meaningful latent features. Getting a z whose entries really correspond to things like "beard" or "viewpoint" needs a good training strategy. One possibility is to train the encoder in a supervised way. Given the image you predict z, with an extra loss forcing z to represent the semantic features. Once trained, you can feed any chosen z to the decoder and get a sample from the conditional distribution.
  2. A prior p(z) to sample from. A plain autoencoder gives no principled distribution over codes to draw from. Fixing this, together with the training objective of the next section, is where the variational autoencoder and the other generative models of later courses take over.

11. Learning the Distribution: KL Divergence and Maximum Likelihood

11.1 How do we measure "as close as possible"?

We want pmodel​ (parameterised by θ) to be as close as possible to pdata​. The most naive loss compares the two densities at each data point:

θmin​∣∣​pdata​(x)−pmodel​(x;θ)∣∣​

This cannot be used directly, because pdata​ is not available to us. We only have samples.

11.2 Kullback–Leibler (KL) divergence

Another way to measure the distance between two distributions is the KL divergence. It equals 0 when the two distributions are identical and takes large values when they differ. We write p(x) for the model's marginal ∫z​p(x,z)dz. The best-fitting distribution minimises

minDKL​(pdata​(x)∥p(x))

11.3 Step-by-step simplification

Apply the definition of KL divergence:

DKL​(pdata​∥p)=∫pdata​(x)logp(x)pdata​(x)​dx

Written as an expectation over x∼pdata​ and split with logba​=loga−logb:

DKL​(pdata​(x)∥p(x))=Ex∼pdata​​[logpdata​(x)−logp(x)]=no model parametersEx∼pdata​​[logpdata​(x)]​​−Ex∼pdata​​[logp(x)]

The first term has no model parameters (θ) in it, so it is a constant for the optimisation and can be ignored. Minimising the KL divergence is therefore the same as maximising the second term:

minDKL​(pdata​(x)∥p(x))⟺maxlogp(x)

Since we have no access to pdata​ itself, the expectation is approximated by the training samples:

This is exactly the maximum log-likelihood estimator. Every generative model is, in some way, trained by maximising the log-likelihood logp(x). This is the starting point of the generative models covered in the coming courses.

Bridge to the autoencoder loss (extra intuition). Suppose the decoder is a Gaussian centred on its output with fixed variance: p(x∣h)=N(g(h),σ2I). Then

−logp(x∣h)=2σ21​∥x−g(h)∥22​+const

So minimising the squared reconstruction error is the same as maximising likelihood under this decoder. The humble autoencoder loss is a maximum-likelihood objective in disguise.

These are meant to make you think and combine ideas. Do not look for formulas to plug into.

  1. The honest bottleneck. You train two linear undercomplete autoencoders on the same mean-centred dataset in R100: one with a code of size 10, one with a code of size 40. Both reach their global minimum of the reconstruction loss. Without running anything, what can you say about how their reconstruction errors relate to the eigenvalues of the data covariance matrix? A colleague now says: "Replace the linear layers by deep ReLU layers and the code of size 10 will always beat PCA with 40 components." Give a situation where this claim is plausible and one where it fails.

  2. The cheating network. An autoencoder with a 1-dimensional code reaches near-zero training loss on 5,000 images but produces garbage when you feed it test images, and shuffling the training set order changes the learned codes completely. Explain what the network has learned. Then design two different fixes (one that changes the loss, one that changes the training input) and explain what each one prevents.

  3. Sparsity without a hard count. The ∥h∥0​ penalty is a count of non-zero entries. Why would it be awkward to train with gradient descent? Using the vectors hA​=(0.9,0,0,0) and hB​=(0.3,0.3,0.3,0.3), compute ∥⋅∥0​, ∥⋅∥1​ and ∥⋅∥2​ for each, and decide which norm would reward hA​ over hB​ in a way that is friendly to gradient-based learning. Justify your answer.

  4. Smooth codes, sharp images. A contractive autoencoder and a denoising autoencoder are both trained on handwritten digits. You then take a digit and move a few pixels in a random direction. Predict how the code h changes under each model and explain why the two models get there by different routes. Which one would you expect to be more helpful if the input at test time is occasionally partly missing, and why?

  5. Steering the sample. Suppose you have trained a stochastic autoencoder whose code z has 6 dimensions, and you want to generate "a smiling person wearing spectacles, viewed from the side". (c) What additional ingredient does a plain autoencoder lack that you would need before you could sample a new z at all? (d) Show why dropping the term Epdata​​[logpdata​(x)] from the KL objective does not change the optimal parameters.
