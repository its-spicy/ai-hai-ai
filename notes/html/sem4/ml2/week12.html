1 Where We Left Off

The problem with fully connected (FC) layers on images. If an image has 3×106 pixel features and every neuron is connected to all of them, each neuron has 3×106 weights. With 1000 neurons that is about 3×109 weights for one single layer, and one layer cannot extract good, compact features anyway.

The fix: convolution as the neuron's basic operation.

  • Each neuron looks only at a local part of the input. The width of the filter decides how much it sees.
  • All neurons of one feature map share the same filter weights.
  • In 1D, a filter [31​,31​,31​] on a 10-sample signal gives an output such as 3 at the first fully overlapped location. An activation function can be applied on top.

Boundaries without padding. Where the filter hangs outside the signal, the output is either dropped (shrinking: input 10, filter 3 gives output 8) or the missing values are invented (padding: zeros, or repeated adjacent values).

2D and colour. The same idea works on images. Without padding, a 5×5 input with a 3×3 filter gives 3×3, and with a 5×5 filter gives 1×1 (only one position has full overlap). If the input has c channels, the filter must have c channels too. The output at one location is the same neuron equation as in an FC network,

z=wTx+b,

except that x is only the small patch under the filter. For a 32×32×3 image and a 5×5×3 filter the output is 28×28.

Different filters, different features. One filter might detect horizontal edges, another vertical edges. The set of K filters forms a convolutional layer and its output is a stack of K feature maps. With K=10 and 5×5×3 filters there are 10×75=750 weights (biases are optional, +10).

Today's hyperparameters (the knobs of a conv layer): number of filters, filter size (f×f; depth is forced by the input), stride, padding, activation function. Then we add one new layer type, pooling, and assemble full networks.

Analogy: Lecture 11 gave us a magnifying glass (the filter). This lecture asks: how far do we move the magnifying glass each time (stride), what do we do at the edge of the table (padding), and how do we shrink the final report without losing the highlights (pooling)?

2 Stride

2.1 What stride is

When the filter slides over the input, it can move by more than one pixel at a time. The stride is the distance (in pixels) the filter moves along the rows and along the columns between two consecutive positions. Earlier we always used a stride of 1.

Working example: input 7×7, filter 3×3, no padding.

2.2 Stride 1

The filter starts at the first valid location (the first position with perfect overlap). It moves 1 pixel to the right each time, and after finishing a row it moves 1 pixel down. The filter's top-left corner can be at column 0,1,2,3,4 (a 3-wide filter starting at column 5 would hang off the edge). That gives 5 positions along the row and 5 along the column:

Output=5×5

2.3 Stride 2

Now we jump 2 pixels, skipping one column each time, and 2 pixels down at the end of each row. The valid start positions along one direction are 0,2,4, so 3 positions:

Output=3×3

2.4 Stride 4

Valid start positions along one direction are 0,4, so 2 positions:

Output=2×2
Stride s Start positions (one direction) Output
1 0, 1, 2, 3, 4 5×5
2 0, 2, 4 3×3
4 0, 4 2×2

Why use a bigger stride? If we want a small number of features quickly, without designing a very deep network, a larger stride reduces the feature map size rapidly. Whether stride 1 or stride 2 works better depends on the data set, so stride is a hyperparameter that must be tuned.

2.5 The general output-size formula

Let the input be n×n, the filter f×f, the stride s (no padding). Then:

Output=(sn−f​+1)×(sn−f​+1)

Verify the two lecture cases:

n=7, f=3, s=1:17−3​+1=5⇒5×5n=7, f=3, s=2:27−3​+1=3⇒3×3

And the stride-4 case:

n=7, f=3, s=4:47−3​+1=2⇒2×2

Note for Review: If sn−f​ is not a whole number, take the floor (as the padding formula in Section 4 does). Example: n=7, f=3, s=3 gives ⌊4/3⌋+1=2, and the last column and row of pixels are never used. A good design makes (n+2p−f) divisible by s.

3 Stacking Conv Layers: a Three-Layer ConvNet

A convolutional layer's input may be an image or the feature volume produced by a previous layer. So we can stack layers. A ConvNet is a concatenation of conv layers and activations.

3.1 The architecture

Input image: 32×32×3. All layers use no padding and stride 1, with ReLU as activation.

3.2 Layer by layer

Conv Layer 1 (5 filters, each 5×5×3)

  • The filter depth is 3 because the input has 3 channels.

  • Spatial size: no padding, filter 5×5, so 2 rows are lost at the top and bottom and 2 columns at the left and right:

    32−5+1=28

  • Each filter gives one 28×28×1 feature map. 5 filters give a volume of 28×28×5.

  • Different filters extract different features. For example, filter 1 might find vertical edges, filter 2 horizontal edges, filter 3 corners, filter 4 circles. These filters are not fixed: they are learnable, so the network learns the features that matter for the task. The same data with a different task will produce different filters.

  • Parameters:

    5×(5×5×3)+5=5×75+5=380

    (the "+5" is one bias per filter).

Conv Layer 2 (8 filters, each 5×5×5)

  • Input is 28×28×5, so each filter must have depth 5. The width and height (5×5) are our choice (we could use 3×3 or 7×7).

  • Spatial size: 28−5+1=24. 8 filters give an output of 24×24×8.

  • Parameters:

    8×(5×5×5)+8=8×125+8=1008

Conv Layer 3 (12 filters, each 5×5×8)

  • Input is 24×24×8, so the filter depth is 8.

  • Spatial size: 24−5+1=20. 12 filters give an output of 20×20×12.

  • Parameters:

    12×(5×5×8)+12=12×200+12=2412
Layer Input Filters Params (with bias) Output
Conv 1 32×32×3 5 of 5×5×3 5×75+5=380 28×28×5
Conv 2 28×28×5 8 of 5×5×5 8×125+8=1008 24×24×8
Conv 3 24×24×8 12 of 5×5×8 12×200+12=2412 20×20×12

Total parameters: 380+1008+2412=3800. Without biases it is 375+1000+2400=3775, since biases are optional.

The pattern: space shrinks, depth grows. The network trades spatial resolution for a richer set of features.

Note for Review: Always tell the filter depth from the input depth, and the output depth from the number of filters. Depth of filters in layer L = number of filters in layer L−1 (here 5, then 8).

3.3 The problem with no padding

Each of these layers shrinks the map by 4 (32→28→24→20). After three layers we are at 20×20. Keep stacking and the spatial size keeps dropping by 4 per layer: 16,12,8,4 and then the next 5×5 filter no longer fits. The lecturer's rough picture is that a few more layers would take the map to 1×1 spatially, with the third dimension equal to the number of filters of the last layer.

Note for Review: With 5×5 filters and stride 1, the map after k layers is 32−4k, so 4×4 is reached after 7 layers and an 8th is impossible. The "1×1" in the lecture is a loose way of saying "it collapses very quickly".

This is acceptable for classification (one label per image), but not for segmentation, where we assign a label to each pixel of the input, so the output must be the same size as the input. A shrinking architecture cannot do that. This is the first reason we need padding.

4 Padding

4.1 Why padding? Two reasons

Reason 1: the output keeps shrinking. Without padding, every layer reduces the map size, so depth of the network is limited and segmentation is impossible.

Reason 2: pixels are not treated equally. Count how many output positions each input pixel contributes to (input 7×7, filter 3×3, stride 1, no padding, so 5×5=25 outputs):

  • A corner pixel contributes to only one output.
  • A pixel next to the corner on the edge contributes to 2 outputs.
  • A middle pixel on the edge contributes to 3 outputs.
  • An interior pixel contributes to the maximum of 9 outputs (one for each of the 3×3 filter positions that cover it).

Heat map of this contribution count:

So without padding the network gives non-uniform weightage to the pixels: the centre is emphasised and the border is under-used. If the border pixels carry important information, we are giving them less weight than they deserve.

Note for Review: In the lecture the centre pixel was counted as contributing to "8" outputs. The correct count for a 3×3 filter is 9 (all nine filter positions cover an interior pixel, provided the map is large enough). The conclusion is unchanged.

4.2 What padding does

Add a border of extra pixels around the input: 1 row on top, 1 row at the bottom, 1 column on the left and 1 column on the right (for a 3×3 filter). Now the filter can be centred on the original corner pixel, so every original pixel is covered more evenly.

What values go in the border?

Type Idea Border values for the row [1,2,5,1,0,3,4]
Zero padding Fill with 0. The most popular. 0, 1,2,5,1,0,3,4, 0
Repeat (replicate) Copy the adjacent edge value. 1, 1,2,5,1,0,3,4, 4
Reflect Mirror the pixels next to the edge. 2, 1,2,5,1,0,3,4, 3

Zero padding is the most famous choice. With a zero border, the filter at the corner multiplies the missing positions by 0, so only real pixels contribute.

4.3 General output-size formula

Input n×n, filter f×f, stride s, padding p (on each side):

Output=(⌊sn+2p−f​⌋+1)×(⌊sn+2p−f​⌋+1)

The "2p" appears because padding is added on both sides.

Check: input 7×7, filter 3×3, padding 1, stride 1:

⌊17+2(1)−3​⌋+1=⌊16​⌋+1=7⇒7×7

So padding 1 with a 3×3 filter and stride 1 keeps the size the same.

Pro-Tip: This often appears on exams regarding "same" padding. For stride 1 the output equals the input when n+2p−f+1=n, i.e. p=2f−1​. So f=3⇒p=1, f=5⇒p=2, f=7⇒p=3. This is why odd filter sizes are so popular: they have a centre pixel and an integer p.

5 The Pooling Layer

5.1 The problem pooling solves

With padding we can keep feature maps the same size, but sometimes we want to reduce the size of the feature maps (less computation, fewer features). Example: a conv layer outputs 224×224×64 (64 filters, each giving a 224×224 map). We want to cut the spatial size by a factor of 2 to 112×112, without changing the number of feature maps (64 stays 64):

224×224×64⟶112×112×64

5.2 The naive way: downsampling

Throw away alternate rows and alternate columns. Take a 4×4×1 map:

⎣⎡​1210​0203​1352​3421​⎦⎤​keep rows 1, 3 and columns 1, 3​[11​15​]

Look at what was lost: the 4 and the 3 (strong activations) were simply discarded because they sat in the removed rows and columns. Downsampling throws away possibly important features.

5.3 The smart way: pooling

Slide a window over the map without overlap (window 2×2, stride 2) and replace each window by one summary number.

Max pooling keeps the largest value in each window. Using the lecture's 4×4 example:

⎣⎡​3020​1431​9316​8237​⎦⎤​

Four 2×2 windows:

Window Values Max Average
Top-left 3,1,0,4 4 43+1+0+4​=48​=2
Top-right 9,8,3,2 9 49+8+3+2​=422​=5.5
Bottom-left 2,3,0,1 3 42+3+0+1​=46​=1.5
Bottom-right 1,3,6,7 7 41+3+6+7​=417​=4.25
Max pool output=[43​97​]Average pool output=[21.5​5.54.25​]

The strong responses (9, 7, 4) survive in max pooling.

5.4 Roles of the two layers

Layer Job
Conv layer Computes a feature in a given region (feature extraction)
Pooling layer Picks the strongest activation in a region (feature selection)

5.5 Hyperparameters and output size

A pooling layer has three hyperparameters:

  1. Filter (window) size f (for example 2×2)
  2. Stride s (for example 2, so windows do not overlap)
  3. Operation (max, average, ...)

There are no learnable weights in a pooling layer, yet it decides which features pass on.

For an input volume of size (w,h,d) the output volume is:

(sw−f​+1, sh−f​+1, d)

The depth d is untouched: pooling acts on each feature map separately. Check: w=h=224, f=2, s=2:

2224−2​+1=111+1=112⇒112×112×64

Analogy: Think of a class photo taken with 224×224 faces. Downsampling is deleting every other row and column of people. Max pooling is asking each 2×2 group "who is the loudest?" and keeping only that person: you keep the strongest signal from every neighbourhood.

6 The CNN Prototype

6.1 Why not just use pixels as features?

Classify an image into 5 classes: car, truck, airplane, ship, horse. One could treat every pixel as a feature and run an SVM. For an image of 200×200 that is 40,000 features, and an SVM on 40,000-dimensional data is hard. Even logistic regression on raw pixels needs at least 40,000 learnable parameters.

The CNN way: let convolutional layers extract a small number of salient features that represent the object for this task, then put a classifier (usually logistic regression) on top. The last layer of a classification CNN is essentially a logistic regression layer.

6.2 The pattern

The pipeline is: [CONV, ReLU] repeated, then POOL, and again, finishing with an FC layer. Early layers keep a lot of spatial detail; each POOL reduces it; by the end only a small number of strong features remain, and the FC layer maps them to class scores. The output scores in the figure rank car highest for a car photo.

7 LeNet: Reading Digits in the 90s

LeNet was proposed by Yann LeCun in the 1990s for digit recognition. It was the first time convolutional networks were proposed. Task: given an image of a digit, decide which of the 10 digits (0 to 9) it is. Input is 32×32×1 (one channel, a grayscale or binary image).

7.1 Architecture

7.2 Dimensions step by step

Step Operation Calculation Result
Input digit image 32×32×1
Conv 1 6 filters, 5×5×1, s=1, no padding 32−5+1=28 28×28×6
Pool 1 average, f=2, s=2 228−2​+1=14 14×14×6
Conv 2 16 filters, 5×5×6, s=1, no padding 14−5+1=10 10×10×16
Pool 2 average, f=2, s=2 210−2​+1=5 5×5×16
Flatten 5×5×16=400 400 features
FC layers as many as you want
Output 10 neurons one per digit 10 probabilities

Key points:

  • The first conv filter has depth 1 because the input has one channel. The second has depth 6 (the number of maps from the first layer).
  • Pooling reduces the size of each map but not the number of maps (6 stays 6, 16 stays 16).
  • We began with 32×32=1024 pixels, and end with only 400 features. With so few features it is fine to use FC layers.
  • The final 10 outputs are probabilities, so a logistic regression (softmax) layer is used on the features.

The layer pattern: Conv → Pool → Conv → Pool → (Conv) → FC.

7.3 Parameter count

The lecture quotes about 60k parameters. With the standard LeNet-5 FC sizes (120 and 84 neurons, which are typical but are not given in the lecture):

Conv 1Conv 2FC 400→120FC 120→84FC 84→10​=6×(5×5×1+1)=156=16×(5×5×6+1)=2416=400×120+120=48,120=120×84+84=10,164=84×10+10=850​Total=156+2416+48,120+10,164+850=61,706≈60k

The two conv layers hold less than 5% of the parameters. Most weights sit in the FC layers, which is exactly why we shrink the input to 400 features before using them.

Pro-Tip: Exams love the question "where are most parameters in a CNN?". Conv layers are cheap in parameters (weight sharing) but expensive in computation; FC layers are the opposite.

9 Practice Questions

Question 1 — Design a network that does not shrink. You must process 64×64×3 images and want the spatial size to stay 64×64 through a layer with 7×7 filters and stride 1. Find the required padding. Then change the stride to 2 with the same padding and filter: what is the output size, and is any row or column of the padded image never used by a filter position? Show the floor calculation and explain what the leftover pixels mean for the "fairness" argument made for padding.

Question 2 — Where is the memory? A conv layer receives 56×56×64 and applies 128 filters of 3×3 with padding 1, stride 1. Compute the output shape, the number of parameters (with biases), and the number of values stored in the output volume. Now insert a 2×2 max pool with stride 2 after it. How do the number of parameters and the number of stored activations change, and which of the two (parameters or activations) does pooling affect? Why is that important when you try to fit a network into limited GPU memory?

Question 3 — Max or average? A 4×4 feature map from an edge-detecting filter is ⎣⎡​0011​0011​8000​0000​⎦⎤​. Apply 2×2 max pooling and 2×2 average pooling (stride 2). Which output makes the isolated strong response at the top right easier to detect, and which one treats the faint block at the bottom left as comparable to it? Then explain what would happen to each output if the strong response moved one pixel to the left (to column 2, row 1 in 1-indexed terms). What does this tell you about how pooling affects sensitivity to small shifts in the object's position?

Question 4 — Counting weights across a LeNet variant. Find every intermediate feature map shape, the length of the flattened vector, and the total number of parameters if there is a single FC layer from the flattened vector straight to 10 outputs. Compare the number of parameters in the conv part with the FC part and say which layer type dominates. What would you change first if you wanted to reduce the total parameters?
