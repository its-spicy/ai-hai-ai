1. Primitive Data Types

The problem. A payroll program must store an employee's age (25), the year (2026), a salary (50000), a country's population (1,400,000,000), a body temperature (36.5), a grade (A) and whether the student passed (true). Using one generic container for everything would waste memory and allow nonsense (a grade of 36.5?).

The intuitive idea. Java asks you to say what kind of value a variable holds before you use it. The kind decides how much memory is reserved and which operations are legal.

The analogy. Think of storage containers: a pill box, a lunch box, a water bottle and a tanker. You can keep one tablet in a tanker, but it is wasteful, and you cannot pour a tanker's worth of water into a pill box. Data types are the container sizes. The analogy stops at one point: Java will refuse (at compile time) to silently squeeze a value into a container that is too small.

The formal concept. Java is a statically typed language: every variable has a declared type fixed at compile time. The simplest types are the eight primitive types, which store the value itself directly (not a reference to an object).

Type Size Stores Range / Notes
byte 8 bits whole number −27 to 27−1, i.e. −128 to 127
short 16 bits whole number −215 to 215−1, i.e. −32768 to 32767
int 32 bits whole number −231 to 231−1 (about ±2.1 billion)
long 64 bits whole number −263 to 263−1 (about ±9.2×1018)
float 32 bits decimal number about 7 significant digits
double 64 bits decimal number about 15 significant digits
char 16 bits one character a single Unicode character such as 'A'
boolean — truth value only true or false

General syntax of a variable declaration:

dataType variableName = value;

The Java implementation. The program below declares one variable of every primitive type and prints each of them.

What the program does. It creates eight variables, one per primitive type, and prints each with a label. Note the two special endings in the literals: L after 1400000000 marks a long literal, and f after 36.5 marks a float literal. A character goes in single quotes ('A'), never double quotes. 

public class DataTypesDemo {
    public static void main(String[] args) {

        byte age = 25;
        short year = 2026;
        int salary = 50000;
        long population = 1400000000L;

        float temperature = 36.5f;
        double pi = 3.14159265;

        char grade = 'A';
        boolean passed = true;

        System.out.println("Age = " + age);
        System.out.println("Year = " + year);
        System.out.println("Salary = " + salary);
        System.out.println("Population = " + population);
        System.out.println("Temperature = " + temperature);
        System.out.println("PI = " + pi);
        System.out.println("Grade = " + grade);
        System.out.println("Passed = " + passed);
    }
}
Age = 25
Year = 2026
Salary = 50000
Population = 1400000000
Temperature = 36.5
PI = 3.14159265
Grade = A
Passed = true

Syntax breakdown.

  • byte age = 25; — byte is the type, age is the variable name (identifier), = is assignment, 25 is the value, ; ends the statement.
  • Java is case-sensitive: Boolean and boolean are different things, and true must be lowercase.
  • System.out.println("Age = " + age); — the + here joins (concatenates) the text "Age = " with the value of age, converted to text. println prints and then moves to a new line; print would stay on the same line.

Why the suffixes? A decimal literal such as 36.5 is a double by default. Putting a double into a smaller float could lose precision, so Java rejects float temperature = 36.5; with a compile-time error (lossy conversion). Writing 36.5f tells Java you really mean a float. Likewise, an integer literal is an int by default; the L suffix is required only when the number is too large for int.

Note for Review: 1,400,000,000 is still smaller than the largest int (2,147,483,647), so here the L is not strictly necessary. It becomes mandatory for literals beyond the int range, and it does no harm here because population is declared long.

Common beginner mistakes.

  • Writing char grade = "A"; — double quotes make a String, not a char. This is a compile-time error.
  • Writing byte age = 200; — 200 is outside −128 to 127, so the compiler rejects it.
  • Treating boolean like a number. Java does not accept 1 or 0 as a boolean.

2. Reading Input with Scanner

The problem. The programs so far use fixed values. A real program (a billing counter, a marks entry system) must accept values typed by the user while it runs.

The analogy. A bank clerk at a counter asks, "Your name?" and then "Your age?", writing each answer on a form. Scanner is the clerk; the keyboard is the customer; each next...() call is one question whose answer is stored in a variable.

The formal concept. Scanner is a class from the package java.util that reads text from an input source. System.in is the standard input stream (the keyboard).

General pattern:

import java.util.Scanner;                     // 1. make Scanner available

Scanner sc = new Scanner(System.in);          // 2. create a Scanner
dataType variable = sc.nextXxx();             // 3. read a value
sc.close();                                   // 4. release the resource

What the program does. It asks for a name and an age, reads them, and prints them back. nextLine() reads an entire line of text (including spaces) as a String, while nextInt() reads the next whole number as an int. The output below corresponds to the user typing Debasis and then 35. 

import java.util.Scanner;

public class InputDemo {
    public static void main(String[] args) {

        Scanner sc = new Scanner(System.in);

        System.out.print("Enter your name: ");
        String name = sc.nextLine();

        System.out.print("Enter your age: ");
        int age = sc.nextInt();

        System.out.println("Name: " + name);
        System.out.println("Age: " + age);

        sc.close();
    }
}
Enter your name: Debasis
Enter your age: 35
Name: Debasis
Age: 35

Syntax breakdown.

Piece Meaning
import java.util.Scanner; Mandatory, placed above the class. Without it the compiler does not know what Scanner is.
Scanner sc Declares a reference variable sc that can refer to a Scanner object.
new Scanner(System.in) Creates the Scanner object and connects it to the keyboard.
sc.nextLine() Reads the rest of the current line as a String.
sc.nextInt() Reads the next token and converts it to int.
sc.close() Closes the scanner when finished.

Execution trace.

Step Operation Result
1 print("Enter your name: ") Prompt appears; cursor stays on the same line
2 sc.nextLine() Program waits; user types Debasis and presses Enter; name holds "Debasis"
3 print("Enter your age: ") Second prompt appears
4 sc.nextInt() User types 35; age holds 35
5 Two println calls Name: Debasis and Age: 35 are printed
6 sc.close() Scanner is closed

Other common read methods (supplementary): nextDouble() for double, next() for a single word, nextBoolean() for boolean.

Note for Review (supplementary): The order in this program is deliberate: nextLine() first, nextInt() second. If you call nextInt() and then nextLine(), the Enter key pressed after the number is still waiting in the input, so nextLine() immediately returns an empty line. Also, typing text such as abc when nextInt() expects a number causes a runtime exception (InputMismatchException).

3. Decision Making with if-else

The problem. A program should behave differently depending on data. For example, tell the user whether a number is even or odd.

The intuitive idea. An even number leaves no remainder when divided by 2. So we test the remainder and choose one of two actions.

The formal concept. The if-else statement runs one block when a condition is true and another block when it is false. The remainder operator % gives the remainder of a division:

nmod2={01​if n is evenif n is odd (for n≥0)​

General syntax:

if (condition) {
    // runs when condition is true
} else {
    // runs when condition is false
}

What the program does. It reads an integer n and checks whether n % 2 == 0. If the remainder is zero it prints Even Number; otherwise it prints Odd Number. With the input 10, the remainder of 10÷2 is 0, so the output is Even Number. 

import java.util.Scanner;

public class EvenOdd {
    public static void main(String[] args) {

        Scanner sc = new Scanner(System.in);

        System.out.print("Enter a number: ");
        int n = sc.nextInt();

        if (n % 2 == 0) {
            System.out.println("Even Number");
        } else {
            System.out.println("Odd Number");
        }

        sc.close();
    }
}
Enter a number: 10
Even Number

Syntax breakdown.

  • The condition goes inside parentheses and must be a boolean expression.
  • == compares two values; = assigns. Writing if (n % 2 = 0) is a compile-time error because n % 2 = 0 is an assignment, not a boolean.
  • Braces { } group statements. They are optional for a single statement, but always using them avoids bugs.
  • The else part is optional.

Trace for input 10.

Step Operation Result
1 n = 10 n stores 10
2 Evaluate 10 % 2 0
3 Evaluate 0 == 0 true
4 Run the if block Even Number is printed
5 else block Skipped

4. Loops: The while Statement

The problem. To print the numbers 1 to 5, writing five println statements works, but printing 1 to 1000 does not. We need to repeat an action while some condition holds.

The formal concept. A while loop checks a condition before every repetition and keeps running its body as long as the condition is true.

General syntax:

while (condition) {
    // body: runs repeatedly while condition is true
}

Note on the source material: The lecture screen titled for the while demonstration shows an output console listing the numbers 1 to 5, but the code visible in that editor tab is the Employee program covered in the next section. The example below is therefore a supplementary reconstruction of a typical counting loop consistent with that output; it is not copied from the lecture.

What the program does. It starts a counter i at 1, prints it, increases it by 1, and repeats until i exceeds 5. Every while loop needs three ingredients: a starting value, a condition, and an update that eventually makes the condition false. 

int i = 1;                  // start
while (i <= 5) {            // condition
    System.out.println(i);
    i++;                    // update
}
1
2
3
4
5

Step i before check Condition i <= 5 Action
1 1 true print 1, i becomes 2
2 2 true print 2, i becomes 3
3 3 true print 3, i becomes 4
4 4 true print 4, i becomes 5
5 5 true print 5, i becomes 6
6 6 false loop ends

Common mistake. Forgetting i++ leaves the condition permanently true, producing an infinite loop. This is a logic error: the code compiles but never stops.

5. Classes and Objects

The problem. A company has thousands of employees, each with an ID, a name and a salary. Creating separate variables like id1, name1, salary1, id2, name2, … is unmanageable, and nothing ties a name to its salary.

The intuitive idea. Bundle the data that belongs together, along with the actions that work on that data, into one unit.

The analogy. A class is like a blank employee record form: it lists which fields exist (ID, name, salary) but contains no actual person. Each filled-in form is an object. One form design, many filled forms. The analogy is slightly loose in one respect: a class can also contain actions (methods), which a paper form cannot.

The formal concept.

  • A class is a blueprint that defines the fields (data) and methods (behaviour) of a kind of object.
  • An object is one concrete instance of a class, created at run time, with its own values for the fields.

General structure of a class:

class ClassName {
    // Fields (variables that describe the object's state)

    // Constructors (covered next section)

    // Methods (actions the object can perform)
}

What the program does. Employee has three fields (id, name, salary) and one method, display(), that prints them. Inside main, an Employee object is created, its fields are filled, and display() is called. The main method sits inside the same class here to keep the example short. 

class Employee {

    int id;
    String name;
    double salary;

    void display() {
        System.out.println("Employee ID: " + id);
        System.out.println("Name: " + name);
        System.out.println("Salary: " + salary);
    }

    public static void main(String[] args) {

        Employee e = new Employee();

        e.id = 1001;
        e.name = "Neha";
        e.salary = 65000;

        e.display();
    }
}
Employee ID: 1001
Name: Neha
Salary: 65000.0

Syntax breakdown.

  • Fields (int id; String name; double salary;) are declared inside the class but outside any method. Each object gets its own copy.
  • Method declaration: void display() { ... } — void means the method returns no value; display is the name; () is an empty parameter list.
  • Object creation has two parts, which can be written separately:
Employee e;            // 1. declare a reference variable (no object yet)
e = new Employee();    // 2. create an object and store its reference in e

new allocates memory for a new Employee and runs its constructor. The result is a reference (address-like handle) to that object, which is stored in e. So e is not the object; it refers to the object.

  • Dot operator: e.id means "the id field of the object that e refers to"; e.display() means "call display on that object".
  • Method call versus declaration: void display() {...} defines the action; e.display(); runs it.
  • Printing versus returning: display() prints values and returns nothing. A method that returns a value would use a non-void type and a return statement.

Why 65000.0? The statement e.salary = 65000; stores the int value 65000 in a double field. Java widens it automatically to 65000.0, and printing a double always shows a decimal point.

Execution trace.

Step Operation Result
1 Employee e = new Employee(); An object is created; e refers to it. Fields start at default values (0, null, 0.0)
2 e.id = 1001; The object's id becomes 1001
3 e.name = "Neha"; The object's name becomes "Neha"
4 e.salary = 65000; salary becomes 65000.0
5 e.display(); Three lines are printed using the object's field values

Note for Review: A field belongs to an object and lives as long as the object does. A local variable (such as e inside main) exists only while its method runs.

Note on file names (supplementary): The lecture shows this same code saved under two different file names (WhileDemo.java and Employee.java). A source file may contain a class whose name differs from the file name only if the class is not public; a public class must match its file name exactly. Compiling WhileDemo.java would produce Employee.class, which you would run with java Employee.

6. Constructors and this

The problem. In the Employee example, an object is first created empty and then filled field by field. A programmer can forget a line, leaving an employee with ID 0 and name null. We want an object to be complete the moment it is created.

The analogy. A college admission form cannot be submitted without a roll number and a name. A constructor plays the role of that admission process: no student record exists until the required details are supplied.

The formal concept. A constructor is a special block of code that runs automatically when an object is created with new, normally to initialize its fields.

General syntax:

ClassName(parameterList) {
    // initialization statements
}

What the program does. StudentConstructor has a constructor that takes a roll number and a name and stores them in the object's fields. In main, new StudentConstructor(101, "Anjali") creates the object and passes the two values to the constructor. Then display() prints the roll number, a space, and the name. 

class StudentConstructor {

    int rollNo;
    String name;

    StudentConstructor(int rollNo, String name) {
        this.rollNo = rollNo;
        this.name = name;
    }

    void display() {
        System.out.println(rollNo + " " + name);
    }

    public static void main(String[] args) {

        StudentConstructor s =
            new StudentConstructor(101, "Anjali");

        s.display();
    }
}
101 Anjali

Syntax breakdown.

  • The constructor name is exactly the class name, and it has no return type, not even void.
  • The parameters rollNo and name have the same names as the fields. Inside the constructor, a bare rollNo therefore means the parameter (the nearest variable), which hides the field.
  • this is a reference to the current object, the one being constructed. So this.rollNo means "the field rollNo of this object", and this.rollNo = rollNo; means "copy the parameter's value into the field".

Common mistake (logic error, not a compile error): Writing rollNo = rollNo; compiles, but it assigns the parameter to itself. The field is never changed, so it keeps the default value 0 and the output would be 0 null.

Why 101 Anjali prints with a space. The expression rollNo + " " + name is evaluated left to right. rollNo + " " joins an int with a String, producing the text "101 "; that text is then joined with name.

Execution trace.

Step Operation Result
1 new StudentConstructor(101, "Anjali") A new object is created; fields start as 0 and null
2 Constructor starts Parameter rollNo = 101, parameter name = "Anjali"
3 this.rollNo = rollNo; The object's rollNo field becomes 101
4 this.name = name; The object's name field becomes "Anjali"
5 Reference returned and stored s refers to the new object
6 s.display(); Prints 101 Anjali

Constructor versus ordinary method.

Feature Constructor Ordinary method
Name Same as the class Any valid identifier
Return type None (not even void) Required (void or a type)
When it runs Automatically at new Only when called
Purpose Initialize the new object Perform an action

Note for Review: In Employee, the call new Employee() worked even though no constructor was written. If a class has no constructor, the compiler supplies a default constructor with no parameters. Once you write your own constructor with parameters, that default is no longer supplied, so new StudentConstructor() (with no arguments) would not compile.

7. Method Overloading

The problem. A billing program needs to add two item prices, three item prices, or two decimal prices. Inventing different names (addTwo, addThree, addDecimals) makes the code harder to remember.

The analogy. A cashier presses the same "TOTAL" button whether there are two items or three; the machine works out which calculation to do based on what was scanned.

The formal concept. Method overloading means defining several methods in the same class with the same name but different parameter lists (different number, types, or order of parameters).

Rules.

  • The name must be the same.
  • The parameter list must differ in number, type, or order.
  • The return type alone does not make two methods different.

What the program does. MethodOverloading defines three versions of add: two ints, three ints, and two doubles. Each call in main is matched to the version whose parameters fit the arguments. The result of each call is printed. 

class MethodOverloading {

    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }

    double add(double a, double b) {
        return a + b;
    }

    public static void main(String[] args) {

        MethodOverloading obj =
            new MethodOverloading();

        System.out.println(obj.add(10, 20));
        System.out.println(obj.add(10, 20, 30));
        System.out.println(obj.add(10.5, 20.5));
    }
}
30
60
31.0

Note on the source material: The lecture shows this program twice (once as MethodOverloading, once with a shortened class name). The logic is identical. One screen displays Area = 1, Area = 25, Area = 20 in the console; that is leftover output from a previous program, not from this code. The output that matches this code is 30, 60, 31.0. Also, the parameter type is written int (lowercase); Int would not compile.

How Java chooses the version.

Call Matching version Reason Output
add(10, 20) add(int, int) Two int arguments match exactly 30
add(10, 20, 30) add(int, int, int) Three arguments; only this version has three parameters 60
add(10.5, 20.5) add(double, double) 10.5 is a double; it cannot go into an int without losing the decimal part 31.0

Syntax breakdown.

  • Each version has its own return type, name, and parameter list. The parameter list is what Java uses to tell them apart.
  • Because add(double, double) returns a double, the sum 10.5+20.5=31.0 prints with a decimal point.
  • Java decides which version to call at compile time, based on the argument types.
  • When both an exact match and a widening match exist (for example add(10, 20) could also fit add(double, double) after widening), Java prefers the exact match.

Invalid example (does not compile): Two methods that differ only by return type.

int add(int a, int b)    { return a + b; }
double add(int a, int b) { return a + b; }   // INVALID: same parameter list

Java cannot decide which one a call like add(10, 20) means, because the call does not mention the return type.

8. Inheritance

The problem. A company has Manager, Clerk, and Engineer employees. All have an ID, a name and a base salary, but each has some extra behaviour. Copying the common code into every class duplicates work and invites inconsistencies.

The analogy. Think of a general Employee record that holds the common data. A Manager is an Employee, so it automatically has everything an Employee has and then adds manager-specific details. (The lecture illustrates the same idea with an Animal and a Dog.)

The formal concept. Inheritance lets one class (the subclass or child) acquire the fields and methods of another class (the superclass or parent) using the keyword extends. It models an is-a relationship: a Dog is an Animal.

General syntax:

class SubClass extends SuperClass {
    // extra fields and methods of the subclass
}

What the program does. Animal has a method eat(). Dog extends Animal and adds its own method bark(). A Dog object is created in main, and it can call both eat() (inherited) and bark() (its own), even though eat() is not written inside Dog. 

class Animal {

    void eat() {
        System.out.println("Animal eats");
    }
}

class Dog extends Animal {

    void bark() {
        System.out.println("Dog barks");
    }

    public static void main(String[] args) {

        Dog d = new Dog();

        d.eat();
        d.bark();
    }
}
Animal eats
Dog barks

Syntax breakdown.

  • class Dog extends Animal — extends followed by exactly one class name. A Java class can extend only one class.
  • Dog d = new Dog(); creates a Dog object. Since Dog inherits from Animal, this object contains everything an Animal has plus bark().
  • extends is used between two classes. (A different keyword, implements, is used when a class adopts an interface; that is a separate topic.)

Execution trace.

Step Operation Result
1 new Dog() A Dog object is created; d refers to it
2 d.eat() Java looks for eat() in Dog, does not find it, then finds it in Animal and runs it: Animal eats
3 d.bark() Found directly in Dog: Dog barks

Note for Review: Inheritance is for genuine is-a relationships. A Dog is an Animal, but an Employee has a salary; the salary is a field, not a parent class.

9. Method Overriding

The problem. Every Employee has a way to compute pay, but a Manager computes it differently (base pay plus bonus). The child inherits the parent's method but needs its own version under the same name, so callers do not need to learn a new method name.

The formal concept. Method overriding happens when a subclass provides its own implementation of a method that it inherited, using the same name and the same parameter list. When the method is called on a subclass object, the subclass version runs.

What the program does. Parent defines display() that prints Parent Method. Child extends Parent and defines its own display() with the same signature, marked with @Override. When display() is called on a Child object, Java runs the child's version, so the output is Child Method; the parent's version is not used. 

class Parent {

    void display() {
        System.out.println("Parent Method");
    }
}

class Child extends Parent {

    @Override
    void display() {
        System.out.println("Child Method");
    }

    public static void main(String[] args) {

        Child c = new Child();

        c.display();
    }
}
Child Method

Syntax breakdown.

  • @Override is an annotation placed just above the method. It is optional, but it asks the compiler to verify that the method really overrides something in a superclass. If the signature does not match (for example you write void display(int x) or misspell disply), the compiler reports an error instead of silently creating a new, unrelated method.
  • The method must have the same name and parameter list as the parent's method.
  • The access level may not be more restrictive than the parent's, and the return type must be the same (or a narrower subtype). These rules are supplementary to the lecture's simple example.

Execution trace.

Step Operation Result
1 new Child() A Child object is created; c refers to it
2 c.display() Java starts the search in Child
3 Match found in Child Child's display() runs
4 Output Child Method (the Parent version is skipped)

Overloading versus overriding.

Aspect Overloading Overriding
Where Within one class Between a superclass and its subclass
Method name Same Same
Parameter list Must differ Must be the same
Purpose Same action on different inputs Replace inherited behaviour
Needs inheritance? No Yes
Example in this week add(int, int) and add(double, double) Parent.display() and Child.display()

Note for Review (supplementary): If a subclass wants to run the parent's version as well, it can call it with super.display(); inside the overriding method. super refers to the parent part of the object, whereas this refers to the current object as a whole.
